# FastAPI + Next.js 标准项目搭建（单仓库通用版）

## 导言

该教程旨在帮助开发者快速搭建一个具备基础工程能力的 Web 应用项目，并尽可能减少重复的脚手架配置工作，让开发者可以把更多精力放在自己的核心业务需求与功能实现上。

本项目基于 `FastAPI + Next.js + Docker Compose` 构建，整理了多数 Web 应用都会用到的基础能力，包括前后端分离、统一接口响应结构、token 鉴权、数据库初始化、前端 axios 请求封装、Docker 一键构建启动、生产环境 Gunicorn 启动、前端同源 API 代理等。

对于个人开发者、小团队或需要快速验证 idea 的项目而言，该模板可以作为一个标准起点。开发者只需要按照本文档完成项目初始化，然后结合自己的业务需求补全页面、接口、数据模型和业务逻辑，即可逐步形成一个完整且可部署的网页应用产品。

注：

1. 本教程适用于具备一定开发经验的从业者、学生或独立开发者。
2. 小白用户需要自行补充 Python、TypeScript、Docker、数据库、前后端接口等基础知识。
3. 当前项目为通用基础模板，不包含完整业务系统，业务逻辑需要开发者自行扩展。

## 技术栈概览

| 模块 | 技术 | 说明 |
| --- | --- | --- |
| 前端框架 | Next.js | 页面渲染、路由、接口代理 |
| 前端语言 | TypeScript | 类型约束与工程化开发 |
| HTTP 请求 | axios | 统一请求封装、token header 注入 |
| 包管理 | pnpm | 前端依赖管理 |
| 构建工具 | Turborepo | 单仓库任务编排与构建缓存 |

## 项目结构

```text
apps/
  backend/
    app/
      api/v1/routers/     # 后端路由模块
      configs/settings.py # 全局配置
      core/               # 数据库、安全相关工具
      middleware/         # 中间件，如鉴权、请求日志
      models/             # Tortoise ORM 数据模型
      schemas/            # 请求参数与响应模型
    scripts/init_db.py    # 数据库初始化脚本
  frontend/
    src/
      api/                # 前端接口函数与类型
      app/                # Next.js 页面
      configs/            # 前端配置
      lib/http.ts         # axios 请求封装
      types/              # 通用类型
docker-compose.yml        # Docker Compose 编排
package.json              # 单仓库 workspace 配置
pnpm-workspace.yaml       # pnpm workspace 配置
turbo.json                # Turborepo 配置
```

## 快速引入

### 1. 准备环境

本地或服务器需要安装：

| 工具 | 作用 |
| --- | --- |
| Git | 拉取源码 |
| Docker | 构建和运行容器 |
| Docker Compose | 编排前后端服务 |
| Node.js | 本地前端开发时使用 |
| pnpm | 本地前端开发时使用 |
| Python | 本地后端开发时使用 |

如果只使用 Docker 启动项目，本地可以不单独安装 Python 和 pnpm。

### 2. 配置环境变量

复制环境变量模板：

```bash
cp .env.example .env
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

然后编辑 `.env`，填写自己的数据库、端口、JWT 密钥等配置。

常用配置说明：

| 配置项 | 说明 |
| --- | --- |
| `POSTGRES_HOST` | PostgreSQL 数据库地址 |
| `POSTGRES_PORT` | PostgreSQL 数据库端口 |
| `POSTGRES_USER` | PostgreSQL 用户名 |
| `POSTGRES_PASSWORD` | PostgreSQL 密码 |
| `POSTGRES_DB` | PostgreSQL 数据库名称 |
| `FRONTEND_PORT` | 前端服务宿主机端口 |
| `BACKEND_PORT` | 后端服务宿主机端口 |
| `BACKEND_BIND_HOST` | 后端绑定地址，默认 `127.0.0.1` |
| `NEXT_PUBLIC_API_BASE_URL` | 前端浏览器 API 地址，默认留空表示同源 |
| `INTERNAL_API_BASE_URL` | Next.js 在 Docker 内部代理后端地址 |
| `JWT_SECRET_KEY` | token 加密密钥 |

创建虚拟环境：


```bash
gunicorn app.main:app -c gunicorn_conf.py
```

## 部署流程

### 1. 拉取代码

```bash
git clone https://github.com/yangzhenyuYUYU/single.git
cd single
```

### 2. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，设置数据库、端口和密钥。

### 3. 启动服务

```bash
docker compose up --build -d
```

### 4. 配置端口

如果服务器 `3000` 端口被占用，可以修改：

```env
FRONTEND_PORT=8080
```

然后重启：

```bash
docker compose down
docker compose up --build -d
```

访问：

```text
http://服务器IP:8080
```

### 5. 域名与 Nginx

生产环境推荐使用 Nginx 监听 `80/443`，再反向代理到前端服务。

示例：

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

后端端口默认绑定 `127.0.0.1`，不建议直接暴露公网。前端会通过 Docker 内部地址代理后端接口。

## 常见问题

| 问题 | 说明 |
| --- | --- |
| 前端能打开但接口不通 | 查看 `docker compose logs -f backend` |
| 登录接口报错 | 检查数据库、默认账号、bcrypt 依赖版本 |
| `/api` 代理失败 | 确认 `INTERNAL_API_BASE_URL=http://backend:8000` |
| Docker 拉镜像失败 | 检查 Docker 镜像源配置 |
| 端口被占用 | 修改 `.env` 中的 `FRONTEND_PORT` 或 `BACKEND_PORT` |
| Redis 不想启动 | 默认已不启动 Redis，可忽略 |
