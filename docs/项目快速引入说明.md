# FastAPI + Next.js 项目快速引入说明

## 项目定位

这是一个 `FastAPI + Next.js + Docker Compose` 单仓库模板，适合作为小型 Web 应用、内部工具或 AI 应用控制台的起点。当前项目已经包含：

- FastAPI 后端、Tortoise ORM、PostgreSQL、可选 Redis
- Next.js 15 前端、同源 API 代理、受保护的 `/dashboard`
- JWT 登录接口 + Next.js HTTP-only cookie session
- OpenAPI 导出、`openapi-typescript` 类型生成、`openapi-ts-fetch` 请求封装
- 环境变量驱动的管理员种子账号和自助注册开关
- Docker Compose 本地/服务器启动流程

源码地址：


## 环境变量

复制模板：

```bash
cp .env.example .env
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

也可以用初始化脚本生成本地 `.env`：

```powershell
.\scripts\init.ps1
```

必须重点确认：

| 配置项 | 说明 |
| --- | --- |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | PostgreSQL 连接信息，密码不要留空 |
| `JWT_SECRET_KEY` | JWT 签名密钥，至少 32 个字符，不要提交到仓库 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 可选管理员种子账号；两者同时设置才会创建或更新管理员 |
| `ENABLE_SELF_REGISTRATION` | 后端 `/api/v1/auth/register` 开关，默认 `false` |
| `NEXT_PUBLIC_ENABLE_SELF_REGISTRATION` | 前端“创建本地账号”按钮开关，默认 `false` |
| `NEXT_PUBLIC_API_BASE_URL` | 浏览器 API base URL；留空表示同源 `/api` |
| `INTERNAL_API_BASE_URL` | Next.js 服务端校验 token 和 rewrite 后端地址，Docker 默认 `http://backend:8000` |
| `BACKEND_BIND_HOST` | 后端宿主机绑定地址，默认 `127.0.0.1` |
| `FRONTEND_PORT` / `BACKEND_PORT` | 前后端映射到宿主机的端口 |

项目没有源码内默认账号或密码。生产或共享环境应使用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 预置管理员，或接入自己的账号体系。

## 账号创建方式

### 推荐：环境变量管理员种子

在 `.env` 中设置：

```env
ADMIN_USERNAME=your-admin
ADMIN_PASSWORD=your-strong-password
```

后端启动时会：

- 创建该账号，或更新同名账号密码
- 启用该账号
- 设置 `role=admin`

如果两个变量都留空，项目不会自动创建账号。

### 本地临时自助注册

自助注册默认关闭。如需本地临时创建账号，同时打开后端和前端开关：

```env
ENABLE_SELF_REGISTRATION=true
NEXT_PUBLIC_ENABLE_SELF_REGISTRATION=true
```

重新构建/启动后，登录页会显示“创建本地账号”。账号创建完成后，建议把两个开关改回 `false` 并重启。

## 实际认证与 Session 流程

当前项目保留后端 JWT 能力，但浏览器端不直接把 token 放进本地存储，也不在页面代码里手动拼 `Authorization` header。

流程如下：

1. 登录页调用 `/api/v1/auth/login`。
2. FastAPI 校验用户名密码，返回 `access_token`。
3. 前端调用 Next.js route `/auth/session`，把 token 交给服务端。
4. Next.js 服务端用 `INTERNAL_API_BASE_URL` 请求 `/api/v1/users/me` 校验 token。
5. 校验通过后，Next.js 设置 HTTP-only cookie：`hyperspace_session`，有效期 1 小时。
6. 访问 `/dashboard` 时，`apps/frontend/src/middleware.ts` 校验 cookie 中的 token；无效则清 cookie 并重定向到 `/`。
7. 浏览器请求 `/api/v1/*` 时，middleware 从 cookie 读取 token，注入后端需要的 `Authorization: Bearer ...` header。
8. 页面代码继续使用同源 `/api/v1/*`，不直接接触 token。

相关文件：

| 文件 | 作用 |
| --- | --- |
| `apps/frontend/src/app/auth/session/route.ts` | 建立和清除 HTTP-only session cookie |
| `apps/frontend/src/auth/session.ts` | token 校验、cookie 写入/清除工具 |
| `apps/frontend/src/auth/session-constants.ts` | cookie 名称和过期时间 |
| `apps/frontend/src/middleware.ts` | 保护 `/dashboard`，为 `/api/v1/*` 注入 Bearer token |
| `apps/backend/app/middleware/auth.py` | 后端 `require_auth` 依赖和 Bearer token 校验 |

## 前端 API 与类型生成

当前请求封装在：

```text
apps/frontend/src/api/client.ts
```

核心约定：

- `openapi-ts-fetch` 负责按 OpenAPI paths 调用接口
- 浏览器端请求使用同源 API，并带上 `credentials: "same-origin"`
- TypeScript 类型来自 `apps/frontend/src/api/generated/schema.ts`
- `apps/frontend/src/api/types.ts` 只导出基于生成类型的别名，不手写重复 DTO
- 页面优先调用 `apps/frontend/src/api/auth.ts`、`apps/frontend/src/api/user.ts` 这样的薄包装

后端 schema 或路由变化后，重新生成：

```bash
pnpm api:generate
```

生成流程：

1. `apps/backend/scripts/export_openapi.py` 导出 `apps/frontend/src/api/generated/openapi.json`
2. `openapi-typescript` 生成 `apps/frontend/src/api/generated/schema.ts`

检查生成文件是否已提交：

```bash
pnpm api:check
```

## 主要模块

| 模块 | 当前能力 |
| --- | --- |
| 登录 | 用户名密码登录，成功后建立 HTTP-only cookie session |
| 注册 | 默认关闭，可通过双环境变量临时开启 |
| 用户 | `users` 表包含 `username`、`hashed_password`、`is_active`、`role`、时间字段 |
| 当前用户 | `/api/v1/users/me` 返回当前用户，包含 `role` |
| Dashboard | `/dashboard` 由 middleware 保护，并加载当前登录用户展示账号状态 |

| Redis | 可选 profile，默认不启动 |

Redis 如需启用：

```bash
docker compose --profile cache up -d redis
```

并按需要设置：

```env
REDIS_HOST=redis
```

## 部署要点

1. 复制 `.env.example` 为 `.env`。
2. 设置强密码和 `JWT_SECRET_KEY`。
3. 用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 预置管理员，或接入自己的账号创建流程。
4. 保持 `ENABLE_SELF_REGISTRATION=false` 和 `NEXT_PUBLIC_ENABLE_SELF_REGISTRATION=false`，除非确实需要开放注册。
5. 建议后端保持 `BACKEND_BIND_HOST=127.0.0.1`，公网只暴露前端或 Nginx。

如果前端端口被占用：

```env
FRONTEND_PORT=8080
```

然后重启：

```bash
docker compose down
docker compose up --build -d
```

生产环境可用 Nginx 反向代理到前端端口：

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 快速验证

健康检查：

```bash
curl http://localhost:3000/api/v1/health
curl http://localhost:8000/api/v1/health
```

登录：

```bash
curl -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"<your-username>","password":"<your-password>"}'
```

默认注册应被禁用：

```bash
curl -X POST http://localhost:3000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"local-user","password":"local-password"}'
```

无有效 session 时访问 `/dashboard` 会重定向到登录页；登录成功并建立 `hyperspace_session` 后，`/dashboard` 会加载当前用户并展示账号状态。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 登录失败 | 检查账号是否由管理员种子创建，或是否临时开启了自助注册 |
| 登录后无法进入 `/dashboard` | 查看前端日志，确认 `/auth/session` 能通过 `INTERNAL_API_BASE_URL` 访问后端 |
| `/api/v1/*` 代理失败 | 确认 `INTERNAL_API_BASE_URL=http://backend:8000`，并重建前端容器 |
| 前端类型不匹配 | 运行 `pnpm api:generate` 并提交 generated 文件 |
| 后端启动失败 | 查看 `docker compose logs -f backend`，检查数据库和 `JWT_SECRET_KEY` |
| Redis 不想启动 | 默认不会启动 Redis，可忽略 |
